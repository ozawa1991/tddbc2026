# ペアプロの決め事

ユーザーと Claude のペアで TDD を進めるときの約束。変えたいときはユーザーが言う。

## 役割

- **ドライバー**: コードを打つ。目の前の 1 手に集中する
- **ナビゲーター**: 方向を考える。次のテスト、命名、設計の違和感を指摘する。打たない
- 打つ前に、次の一手を一言で宣言する (「次は空文字のテストを書きます」)
- ナビゲーターは理由つきで指摘する。決められないときはユーザーが決める

## 交代 (ピンポン方式)

1. A が失敗するテストを 1 つ書く (赤)
2. 赤を確認したら交代。B が最小の実装で通す (緑)
3. B がリファクタして、コミットする
4. B が次の失敗するテストを書く。以降 A と B を入れ替えて繰り返す

- 上の流れが 10 分以上止まったら、サイクルの途中でも交代する
- ユーザーがドライバーのとき、Claude は答えのコードを書かずヒントと次のテスト案を出す
- 交代の前に必ず今の状態を言う (どのテストが赤/緑か、次に何をするか)

## テストリスト

- 最初に TODO.md にテストの一覧 (やることリスト) を書く。1 行 1 振る舞い
- 通ったら消す。思いついたら足す。実装中に思いついた脇道は一覧に書くだけで、今は手を付けない

## セッションの切り替え

次のとき、サイクルの区切り (緑でコミット済み) で新しいセッションに切り替える。

- 会話が長くなり、前の経緯があいまいになってきた
- 担当を替えて、別の人のセッションが続きを引き継ぐ

切り替える手順:
1. すべてコミットする。ワークツリーは clean にする
2. TODO.md を最新にする
3. 引き継ぎメモを 3 行で出す: 今どのテストまで通ったか / 次にやること / 決めた設計方針
4. 新しいセッション (`/clear` か新規起動) で、`git log --oneline` と TODO.md を読んでから再開する
